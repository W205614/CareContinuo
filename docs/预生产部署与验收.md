# 预生产部署与验收

本环境用于在一台 Docker 主机上验证单院多科室流程。两个 API 副本和两个 Worker 共用 PostgreSQL。Nginx 只发布环回 HTTPS，Keycloak 使用独立合成身份，Agent 使用模型替身。

## 从源码启动

在仓库根目录运行。需要 Docker Engine 与 Compose、Python 3.12 或更高版本及 OpenSSL。Windows 可用相同命令，通过 `--openssl` 指向可用的 OpenSSL 可执行文件。准备脚本为新目录生成临时证书、OIDC 测试身份和配置，目录应保存在不入库的 `.local`。

```sh
python deploy/preprod/prepare.py .local/preprod
docker compose -f compose.preprod.yaml --env-file .local/preprod/compose.env -p carecontinuo-preprod build
docker compose -f compose.preprod.yaml --env-file .local/preprod/compose.env -p carecontinuo-preprod up --no-build --wait --wait-timeout 180
curl --cacert .local/preprod/tls_cert.pem --fail https://127.0.0.1:18443/api/v1/status
curl --cacert .local/preprod/tls_cert.pem --fail --retry 15 --retry-all-errors --retry-delay 2 \
  https://127.0.0.1:18443/id/realms/care/.well-known/openid-configuration
python deploy/preprod/control.py --env-file .local/preprod/compose.env seed
```

`prepare.py` 的 `--port` 可跳开本机端口占用。并行运行其他合成预生产项目时，给每个项目显式指定不同的 `-p`、证书目录、端口和 `CARE_PREPROD_SUBNET_PREFIX`。后者填写未被宿主机或 Docker 使用的前三段 IPv4，默认为 `10.203.200`。

打开 [预生产入口](https://127.0.0.1:18443)。`staff.json` 保存本地生成的合成工作人员凭据和 OTP 种子。患者账号为 `load-1` 至 `load-320`，合成密码见该目录的 `patient_password`。所有文件仅用于该环境。浏览器与 API 客户端可使用生成的 `tls_cert.pem` 信任本地测试证书。

| 组件 | 配置和权限 |
| --- | --- |
| HTTPS 入口 | Nginx 独立 TLS 文件、登录限流、附件限额。API、数据库、管理指标和 Agent 地址在容器网络内。 |
| API | `preprod` 配置使用安全 Cookie 和 PostgreSQL 会话，OIDC 由签发者、授权端点、令牌端点、公钥端点、客户端及所需 `acr` 决定。工作人员须已在应用登记。 |
| Worker | `preprod,worker` 启用后台调度。与 Agent 共用只读内部密钥文件，模型替身支持超时和迟到结果验证。 |
| 数据库 | Flyway 由 `care_migrator` 先执行。API 和 Worker 由 `care_app` 访问业务及会话表，审计为追加写入。 |

`carecontinuo-preprod_pgdata` 保存数据库。停止保留卷，查看 `ps` 及指定服务日志定位问题。登录失败时核对签发者、应用登记的 Subject、回调 URL 和 MFA 的 `acr`。数据库中断时就绪探针失败，存活探针继续工作。应用容器的 8081 端口提供 Prometheus、就绪和存活指标，浏览器入口不转发管理端点。

## 合成回归、容量和供应链检查

演示版回归见 [贡献指南](../CONTRIBUTING.md#测试)。预生产在 `web` 安装依赖和 Chromium 后运行。Linux/macOS 的环境变量可直接用于命令，Windows PowerShell 使用 `$env:CARE_PREPROD_ORIGIN = 'https://127.0.0.1:18443'` 等对应设置。

```sh
cd web
npm ci
npx playwright install chromium
CARE_PREPROD_ORIGIN=https://127.0.0.1:18443 npx playwright test -c playwright.preprod.config.ts
cd ..
```

预生产测试在请求前核对 Web、PostgreSQL、端口和 Compose 项目标记。默认使用 300 个独立患者争抢 50 个号源。CI 当次回归可设置 `CARE_PREPROD_HOTSPOT_CLIENTS` 缩短竞态测试。使用不同目录时同步配置 `CARE_PREPROD_FIXTURES` 和 `CARE_PREPROD_PROJECT`。

```sh
python deploy/preprod/pressure.py --env-file .local/preprod/compose.env
python deploy/preprod/pressure.py --env-file .local/preprod/compose.env --duration 2h --report endurance.json
./mvnw -B dependency:resolve
python deploy/preprod/scan.py .local/preprod/scans
```

k6 的默认负载为 200 个活跃患者会话、100 请求/秒、30 分钟，走排班、预约、退改约、随访和站内消息。短跑可通过 `--clients`、`--rate`、`--duration` 设置。压力脚本使用独立夹具并通过 PostgreSQL 核对通知时延。登录阶段验证环回 HTTPS 的测试证书，k6 只接入该 Compose 项目的容器网络。输出在环境目录的 `reports`，会话夹具含临时 Cookie，请勿提交或共享。

扫描脚本从 Git HEAD 导出源码，并读取本机 Maven 缓存。API 的 Java 依赖由 Syft 从实际镜像生成清单，再交给 Trivy 扫描。Trivy 还检查 API 基础系统、镜像凭据及 Web、Agent 镜像。每次扫描选择一个新的输出目录，以保留原始报告。高危、严重和凭据发现会使检查失败。

## 升级、备份和恢复

```sh
python deploy/preprod/upgrade.py --env-file .local/preprod/compose.env
python deploy/preprod/control.py --env-file .local/preprod/compose.env backup .local/preprod/rehearsal.dump
python deploy/preprod/control.py --env-file .local/preprod/compose.env restore .local/preprod/rehearsal.dump
```

升级演练在独立库建 V7 样本、应用后续迁移并核对预约、库存和科室。现有排班按迁移时医生的科室回填，门诊资料沿用关联排班科室，旧出院资料回填至「全科门诊」。部署到有历史数据的环境前，请由业务负责人核对曾经调科的医生、排班和出院资料的实际归属。

变更前先记录应用镜像摘要、数据库版本和备份校验值。备份默认排除会话内容，恢复到新命名的独立数据库并输出数据核对结果及恢复耗时。以 1 小时内的数据恢复点作为预生产目标时，备份间隔需留出单次备份与复制的时间。正式部署还需使用加密、异盘或跨故障域备份。应用回滚前核对镜像与当前 Flyway 版本的兼容性，必要时先验证迁移前备份，再切换到已恢复的数据库。

## 验收证据

以下为合成数据结果。主机使用 AMD Ryzen 5 6600H（6 核、12 线程）。Docker Desktop Linux/amd64 虚拟机分配 12 个逻辑 CPU 和约 15.2 GiB 内存。两台 API 和两台 Worker 各限制在 2 核及 1.5 GiB，单 PostgreSQL 限制在 4 核及 4 GiB。本轮数据库索引改进后的候选工程提交为 `971466f`。

| --- | --- |
| AC-01～09 回归 | 本机 Playwright 17 项通过，覆盖停诊竞态、幂等、会话撤销、资料更正、迟到 Agent 结果和复诊。 |

按[需求文档 AC-10～14](../CareContinuo-需求文档.md#8-多科室预生产)核对通过条件。30 分钟容量、2 小时持续运行和安全扫描由各自报告判定。

2026-11-21 在同一 V12 工程提交和镜像下完成两轮测试，时间均为北京时间。每轮使用 200 个独立患者会话，创建 120 个各有 500 个号的测试时段和 200 项已派发随访。压测走双副本 HTTPS 入口，混合排班、预约、退改约、随访读写和站内消息。两轮均达到 AC-13 的 API 延迟、错误率、丢弃迭代和通知时延门槛。
