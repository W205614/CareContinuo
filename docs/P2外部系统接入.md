# P2 外部系统接入

CareContinuo 的外部适配器入口为 `IntegrationPorts`。当前单院的合成环境继续使用本地预约、站内通知和人工审核。接入时在独立部署配置中实现所需端口，由医院或服务商提供接口版本、鉴权、字段映射、状态字典、沙箱和测试凭据。每家机构先做只读同步和合成联调，再逐步打开写入。真实产品行为以其接入验收为准。

| 端口 | 如何接入 | 联调验收 |
| --- | --- | --- |
| `SchedulingFeed` | 将 HIS 医生、科室和时段标识映射到院内排班。按游标拉取变化，以机构、事件 ID 和版本判重。确认哪个系统拥有库存写入权后再开放预约变更。 | 同一事件重放时库存只变一次。历史修订、停诊及乱序事件保留可追溯结果。 |
| `ClinicalFeed` | 映射患者、接诊、科室和出院标识。对接出院小结及 LIS 检查结果只读流。按授权读取源文件，提交到已有资料版本和医护审核流程。 | 核对患者归属、来源版本、已撤回或更新结果。由医护确认可以公开的内容。 |
| `NotificationGateway` | 对接短信等渠道。将站内事件转换为服务侧模板代码与短期动作引用，按事件标识重试、查询投递状态。接收方联系信息通过机构授权目录解析。 | 合成号码验证重复投递、失败和回执。区分渠道受理、送达、患者已读及人工联系，无需发送病历、结果正文或诊断。 |
| `DocumentRecognition` | 对扫描件提供按页行编号的文本，与 PDF 原件版本关联。按机构批准的模型和资源范围运行识别，由医护复核后再作为随访出处。 | 实测无文本层、多页、双栏、表格和模糊页。抽查漏行、错行、上一页和下一页的引用隔离。 |
| `PaymentGateway` | 将预约、金额币种、支付方和医保资格映射到机构的订单。以幂等键提交，后端查单核实最终状态。机构另行确定退号、退费、撤销及对账规则。 | 用沙箱覆盖失败、重复回调、金额不一致、退费和预约取消。确认预约状态、库存和账务能按双方规则对账。 |
| `VideoGateway` | 给已确认预约创建受限会话。进入权限按实际就诊人和医生校验，通过服务端发行短期参会凭证。结束后撤销凭证并记录必要的会话状态。 | 用合成预约覆盖时间窗口、其他账号加入、取消预约和退出会话。 |
| `InstitutionExchange` | 由双方确认机构标识、医生权限、患者授权范围与撤销规则后交换最小资料引用。接收端按机构和对象独立鉴权后取件。 | 验证同编号患者跨机构时互不可见，撤销后无法获取新内容，交换确认及访问事件可追溯。 |
| `VisitPreparationAssistant` | 传入由患者明确提交的自述，返回可编辑的摘要草稿。来源始终保留为患者自述，经患者确认再提交给接诊医护。 | 核对遗漏、擅自添加的内容、患者改写和未经确认的草稿是否可见。 |
| `MedicationReferenceFeed` | 接入机构采用的药品说明书目录，按通用名、剂型、规格匹配版本。医护核对并确认对患者展示的说明。 | 覆盖同名不同规格、来源失效和未确认说明的页面权限。 |
| `HospitalWorkflowFeed` | 由医院定义住院、出院、转科和会诊状态，以及各时点的负责人和对象访问范围。逐类映射状态后再接收事件。 | 用合成记录演练接诊交接、调科、会诊撤销、历史追溯和多角色权限变化。 |
| `IdentityLinkVerifier` | 接入机构认可的家庭或监护关系证明。调用端以基础身份核验结果另做患者同意、操作范围、有效期和撤销。 | 覆盖错绑、冒用、过期、撤销、代办操作归属和代理人会话。 |

## 接入顺序

1. 确定机构和数据责任人、沙箱地址、账号、字段字典。固定患者和机构标识映射，明确写入主系统、冲突处理与对账办法。
2. 为一个端口实现适配器，按部署配置绑定。凭据由现有密钥管理渠道注入。生产角色、网关或回调地址在机构批准后配置。
3. 校验请求签名和来源、操作时限与幂等键。向本地服务提交时重用对象授权、审核和预约事务。监控只记录必要的系统标识和状态。
4. 以合成数据验证回退、重放、停机恢复、权限撤销和异常差错处理。再用获授权的验证数据验收当前集成版本。

多机构隔离、跨科室会诊和住院管理需要明确组织边界及状态规则。它们会改变当前单院对象授权和工作流，`InstitutionExchange` 只定义机构之间的交接契约。临床场景中的患者自述摘要和用药说明需要由实际负责人确认内容、来源和审核流程。
