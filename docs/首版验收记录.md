## 本机角色和恢复验收

- 日常环境 `carecontinuo` 在本机端口 `18080`。运营在浏览器放号，随访员登记合成出院记录并提取 GPT 候选，医生审核派发。患者甲读取站内消息并从随访任务预约复诊，患者乙访问该任务得到 `404`。
- 真实模型是 `gpt-6.2-sol`。通过 Java 任务调用容器内 Python 服务，从合成小结得到 1 条候选。引用文字能对应原文中的 `2027-01-15`，医护通过自己的账号采纳并提交审核。CI 使用模型替身，可重复覆盖故障和资料更正。
- 隔离环境 `carecontinuo-accept` 停止 Java 服务后将一条待发提醒调整到期。重新启动 Java 后诊疗记录计数一致，该事件进入 `SENT` 且仅生成 1 条站内消息。
- 患者端真实截图见[复诊预约演示](images/revisit-demo.png)。验收范围为本机业务正确性与基础并发，真实院内集成、高负载表现和真实数据合规留待后续阶段。

- 随访员在 Edge 登记一份合成出院小结并发起一次提取。Agent 任务进入 `READY`，OpenAI 返回模型标识 `gpt-6.2-sol`，生成一条 `REVISIT` 候选。从发起到读到已就绪状态约 6.4 秒。
- 候选日期为 `2026-12-09`，逐字引用为「请于 2026-12-09 到全科门诊复诊。」随访员在页面定位原文，采纳候选并提交审核，任务进入 `IN_REVIEW`，草稿保留原文出处。
- 审核医生用独立会话定位并核对同一原文。任务最终进入 `APPROVED`，保存一条审核通过记录。本次验收截至审核通过。
