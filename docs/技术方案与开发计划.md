# CareContinuo 首版技术方案与开发计划

本文记录首次交付的技术方案与阶段安排。现行范围、业务规则及验收编号见[需求文档](../CareContinuo-需求文档.md)。采用单机构、单科室、一种出院随访模板及合成数据。按工程基线、挂号与接诊、人工随访、GPT 草稿、复诊回流、Docker 角色验收、交付文档推进。每阶段通过本地验证后提交至同一分支和 PR，核实该提交的远端 CI 后再进入下一阶段。

## 组件和数据所有权

- Java 21、Spring Boot 4.1、Spring JDBC、Flyway 与 PostgreSQL 17 负责业务和数据一致性。按身份、排班、挂号、接诊、诊疗资料、随访、通知和审计划分。
- Vue 3、TypeScript、Vite 和 Vue Router 提供患者、医生、随访和运营入口。浏览器通过同源反向代理访问 `/api/v1`，使用会话 Cookie 加 CSRF 校验。
- Python 3.13 Agent 通过内部 HTTP 接收冻结版本的文本片段，使用 `gpt-6.2-sol` 的 Responses API Structured Outputs。Java 校验出处、当前版本、任务和权限。候选内容经医护审核后方可派发。测试使用合成资料，真实 GPT 验收从本机只读密钥文件加载凭据。
- Docker Desktop 通过 Compose 管理 `web`、`api`、`agent`、`postgres`，仅 Web 绑定本机端口。测试与日常服务分别使用独立项目、端口与数据库卷。

| 领域 | 数据与接口 | 关键约束 |
| --- | --- | --- |
| 身份与排班 | `app_user`、`user_role`、`patient`、`department`、`doctor`、`schedule_slot`。会话、排班维护及可约时段接口。 | 角色和对象级授权，患者归属由登录账号确定。 |
| 挂号与接诊 | `appointment`、`appointment_action`、`idempotency_request`、`encounter`。预约、退改约、签到、停诊、接诊及更正。 | 时段锁序列化库存和停诊，改约同事务成功或回滚。保护有效预约唯一性，重放返回原结果。 |
| 出院与随访 | `care_episode`、`source_document`、`document_version`、`followup_task`、`followup_revision`、`followup_review`、`followup_feedback`。资料、审核、派发及反馈接口。 | 门诊与住院交接分开。资料不可变，审核、派发、资料更正和通知以诊疗记录为并发边界。|
| Agent 与通知 | `agent_job`、`outbox_event`、`inbox_message`、`work_item`、`audit_log`。生成状态、消息、已读、补发与待办。 | 事件与业务同事务；旧提醒失效；发送、已读和人工联系分别记录。 |
| 复诊 | `followup_appointment`。从随访入口预约并读取预约、接诊与核实记录。 | 通过原挂号逻辑扣号，保留取消、停诊和改约历史。 |

## 阶段验收

| 阶段 | 验收 |
| --- | --- |
| 工程基线 | 组件可构建，Flyway 迁移空库，经浏览器验证反向代理、登录、退出。 |
| 挂号与接诊 | AC-02～04。验证并发库存、幂等、改约失败、停诊竞态、签到及人工更正。 |
| 人工随访 | AC-05、06 的人工与通知部分，AC-08、09。覆盖资料更正、通知恢复、交接与越权。 |
| GPT 草稿 | AC-05、06、09 的 AI 部分。检查冲突原文、超时、出处、迟到和过期结果。 |
| 复诊回流 | AC-01、07，完整回归 AC-01～09。区分预约、接诊、患者自述和医护结论。 |
| Docker 验收 | 实际体验各账号角色，以合成资料验证真实 GPT。重启后确认数据和待处理事件可恢复。 |
| 文档及清理 | 角色验收后提交 `AGENTS.md`、`CONTRIBUTING.md`、`SECURITY.md`，验证 GitHub 私密报告入口。按 `project-readme` 最后提交 README。核验远端 CI 后按项目边界清理多余 Docker 资源和可恢复的本地构建产物。 |

演示时间按 `Asia/Shanghai` 展示。退改约和预约截止开诊前 30 分钟。签到窗口为开诊前后各 15 分钟。通知重试间隔 1、5、15 分钟，达到上限后转人工。出院资料支持手工录入、UTF-8 文本与文本 PDF。OCR、就诊前摘要、用药查询和真实医疗系统接入排到后续版本。交付为源代码和本地运行环境。
